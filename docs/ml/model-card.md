# Model Card

## Общая информация

**Название модели:**
YOLOS (tiny-sized), `hustvl/yolos-tiny`

**Источник:**
[Hugging Face Hub — hustvl/yolos-tiny](https://huggingface.co/hustvl/yolos-tiny)

**Автор / организация:**
Yuxin Fang, Bencheng Liao, Xinggang Wang и др. (HUST Vision Lab, Huazhong University
of Science and Technology). Карточку модели на Hugging Face написала команда
Hugging Face, а не авторы модели.

**Задача модели:**
Детекция объектов на изображении (object detection).

**Архитектура:**
Vision Transformer (ViT), обученный с функцией потерь DETR (bipartite matching loss
и венгерский алгоритм сопоставления). Модель предсказывает до 100 объектов
на изображение.

**Язык:**
Не применимо — модель работает с изображениями. Названия классов на английском
языке (классы COCO).

**Лицензия:**
Apache-2.0.

## Использование в проекте

Модель используется в сервисе EdgeCrafter-TOD как основа детектора малых объектов
на аэроснимках. Выбрана tiny-версия, потому что она компактная и подходит для запуска
на edge-устройствах.

Исходная модель обучена на COCO и не знает классов аэроснимков, поэтому в проекте
она дообучается на датасете AI-TOD-v2 (8 классов: самолёт, мост, резервуар, судно,
бассейн, транспортное средство, человек, ветрогенератор).

Порядок работы в сервисе (см. [UC-01](../project/requirements.md) и
[диаграмму последовательности](../project/diagrams.md)):

1. Оператор отправляет снимок через `POST /detections` ([API](../api/index.md)).
2. Сервис разбивает снимок на фрагменты 800×800 пикселей и передаёт их модели.
3. Модель возвращает рамки, классы и уверенность для каждого фрагмента.
4. Сервис объединяет результаты, применяет порог уверенности и сохраняет результат
   с указанием версии модели (`modelVersion`).

## Входные данные

RGB-изображение. Перед подачей в модель изображение нормализуется и масштабируется
с помощью `YolosImageProcessor`. В проекте на вход подаются фрагменты аэроснимков
размером 800×800 пикселей.

## Выходные данные

Для каждого из 100 «объектных запросов» модель возвращает:

- логиты классов (включая класс «нет объекта»);
- координаты рамки (`pred_boxes`) в нормированном виде.

После постобработки (`post_process_object_detection`) получается список объектов
с классом, уверенностью и координатами рамки в пикселях. Этот список сервис
возвращает в поле `objects` ответа API.

## Метрики качества

По данным карточки модели: **AP = 28.7** на валидационной выборке COCO 2017.

Метрики на аэроснимках и малых объектах авторами модели не указаны.
Для проекта качество после дообучения нужно измерять на тестовой части AI-TOD-v2
(метрики AP, AP<sub>vt</sub>, AP<sub>t</sub> — для очень маленьких и маленьких объектов).

## Ограничения

Указано авторами / в карточке модели:

- модель обучена на COCO 2017 и распознаёт только 80 классов COCO — без дообучения
  она не подходит для классов аэроснимков;
- модель предсказывает не более 100 объектов на изображение (N = 100 объектных
  запросов);
- точность tiny-версии (AP 28.7) заметно ниже, чем у base-версии YOLOS (42 AP),
  — это плата за малый размер модели.

Потенциальные ограничения для нашего проекта:

- на аэроснимках бывает больше 100 объектов на кадр (стоянки, порты), поэтому
  снимки приходится резать на фрагменты, иначе часть объектов будет потеряна;
- объекты размером 2–16 пикселей значительно меньше типичных объектов COCO,
  поэтому качество на них нужно отдельно проверять после дообучения;
- модель обучалась на фотографиях «с земли», а не на снимках сверху — без дообучения
  качество на аэроснимках будет низким.

## Не рекомендуется использовать

- для принятия решений без проверки человеком (военные, правоохранительные
  и другие критичные задачи);
- для слежки и идентификации конкретных людей — модель находит только сам факт
  наличия объекта класса «человек»;
- на снимках другого типа (тепловизионные, радарные, ночные) без отдельной проверки
  качества;
- без дообучения на аэроснимках — исходная модель не рассчитана на вид сверху.
