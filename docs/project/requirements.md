# Требования

## User Stories

### US-01. Детекция объектов на снимке

Как оператор мониторинга,
я хочу загрузить аэроснимок и автоматически получить найденные на нём объекты,
чтобы не просматривать весь снимок вручную.

Критерии приёмки:

- система принимает снимок в формате PNG, JPEG или TIFF размером до 50 МБ;
- после обработки отображается список объектов с классом, координатами рамки и уверенностью;
- если файл не является изображением или повреждён, пользователь получает сообщение об ошибке.

### US-02. Подсчёт объектов по классам

Как оператор мониторинга,
я хочу видеть количество найденных объектов каждого класса,
чтобы быстро оценить обстановку на снимке (например, загруженность стоянки или порта).

Критерии приёмки:

- в результате детекции есть сводка «класс — количество объектов»;
- в сводку попадают только объекты с уверенностью не ниже заданного порога;
- оператор может изменить порог уверенности (от 0 до 1) при отправке снимка.

### US-03. Контроль версии модели

Как ML-инженер,
я хочу видеть, какая версия модели обработала каждый снимок,
чтобы сравнивать качество версий и разбирать ошибки детекции.

Критерии приёмки:

- в каждом результате детекции указана версия модели;
- результат можно повторно получить по его идентификатору;
- если результат с таким идентификатором не найден, система возвращает понятную ошибку.

## Use Case

### UC-01. Детекция объектов на аэроснимке

**Актор:** оператор мониторинга

**Цель:** получить список малых объектов, найденных на аэроснимке.

**Предусловие:** оператор авторизован в системе, у него есть аэроснимок.

**Основной сценарий:**

1. Оператор загружает аэроснимок и при необходимости задаёт порог уверенности.
2. Система проверяет формат и размер файла.
3. Система разбивает большой снимок на фрагменты (тайлы) и передаёт их ML-модели.
4. ML-модель находит объекты на каждом фрагменте и возвращает рамки, классы и уверенность.
5. Система объединяет результаты, отбрасывает объекты ниже порога и сохраняет результат.
6. Оператор видит снимок с рамками объектов и сводку по классам.

**Альтернативные сценарии:**

- *2а.* Файл не является изображением или превышает допустимый размер — система
  сообщает об ошибке, и сценарий завершается.
- *4а.* Модель временно недоступна — система ставит снимок в очередь и
  подтверждает это ответом `202 Accepted` со статусом `queued`. Оператор
  получает результат позже по идентификатору, когда статус станет `completed`.

**Результат:** объекты на снимке найдены и сохранены, либо оператор получил
сообщение о причине, по которой обработка невозможна.
